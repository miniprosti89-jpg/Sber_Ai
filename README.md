## О проекте

**ХелпИнатор** — веб-прототип ИИ-помощника для пациентов государственной системы здравоохранения РФ. Помощник сопровождает пользователя на всех этапах цифрового взаимодействия с ЕМИАС:

- ведёт диалог и собирает **первичный анамнез** перед приёмом у терапевта;
- автоматически определяет **уровень триажа** (зелёный / жёлтый / красный) и предупреждает о неотложных состояниях;
- формирует структурированный **SOAP-протокол** и передаёт его в ЕМИАС;
- **отправляет PDF-протокол врачу** на указанный пациентом email;
- распознаёт справки и рецепты (**OCR**) и ведёт **календарь приёма препаратов**;
- поддерживает **напоминания** о приёме лекарств.

Проект полностью работает **на локальной LLM** — модель `Qwen 2.5 (3B)` развёрнута через **Ollama**. Никакие медицинские данные не покидают контур — важное условие для соответствия 152-ФЗ.

## Ключевые сценарии

### 1. Сбор первичного анамнеза (чат)
Пользователь описывает симптомы свободным текстом. ИИ задаёт уточняющие вопросы (длительность, интенсивность, сопутствующие симптомы, принимаемые препараты), формирует журнал жалоб и итоговый SOAP-протокол.

### 2. Триаж (маршрутизация по уровню срочности)
На каждой реплике пациента срабатывает двухуровневый триаж:
- **Red** — правила регулярных выражений + LLM-классификатор для неотложных состояний (боль в груди, инсульт, судороги, кровотечение, суицидальные мысли). Пациент немедленно получает инструкцию позвонить в **112/103**.
- **Yellow** — потенциально опасные, но не критические симптомы.
- **Green** — плановый визит.

### 3. Формирование SOAP-протокола и передача в ЕМИАС
Протокол структурирован по стандарту SOAP (Subjective / Objective / Assessment / Plan) и доступен для скачивания в PDF.

### 4. Отправка PDF врачу на email
Пациент указывает email врача (по умолчанию подставляется его собственный) — протокол уходит письмом через SMTP с вложением.

### 5. OCR и календарь приёма препаратов
Загрузка фото/PDF справки или рецепта → распознавание → автоматическое добавление препаратов в «Мои рецепты».

### 6. Напоминания о приёме
Пользователь указывает препарат и время — браузер шлёт системное уведомление в нужный момент.

**Ключевые компоненты:**

| Слой | Что делает |
|---|---|
| **Frontend** | Верстка, навигация между 3 режимами (чат / SOAP / календарь), локальная валидация, работа с cookie-сессией |
| **Backend (FastAPI)** | Все API-эндпоинты, оркестрация LLM, работа с сессиями, генерация PDF, отправка email |
| **Ollama + Qwen2.5:3b** | Локальная языковая модель: уточняющие вопросы по анамнезу + LLM-триаж неотложных состояний |

## Установка локальной LLM (Qwen)

Проект использует **локальную модель Qwen**, развёрнутую через **Ollama**. Это критично для соблюдения 152-ФЗ: медицинские данные не уходят в облако.

### 1. Установите Ollama

**Linux / macOS:**
```bash
curl -fsSL https://ollama.com/install.sh | sh
```

**Windows:** скачайте установщик с [ollama.com/download](https://ollama.com/download).

### 2. Загрузите модель Qwen

Рекомендуемая конфигурация для прототипа — компактная `qwen2.5:3b` (быстрая, работает на CPU, занимает ~2 ГБ):

```bash
ollama pull qwen2.5:3b
```

Если есть GPU или хочется более качественных ответов — можно взять старшую модель:

```bash
ollama pull qwen2.5:7b        # ~4.5 ГБ
ollama pull qwen3:8b          # Qwen 3, если доступна в вашей Ollama
```

### 3. Проверьте, что модель отвечает

```bash
ollama run qwen2.5:3b "Привет, представься одной строкой"
```

### 4. Убедитесь, что сервер Ollama поднят

По умолчанию Ollama слушает `http://127.0.0.1:11434`. Быстрая проверка:

```bash
curl http://127.0.0.1:11434/api/tags
```

### 5. Укажите модель в переменных окружения (опционально)

Если используете другую модель или Ollama на другом хосте:

```bash
export OLLAMA_URL="http://127.0.0.1:11434/api/chat"
export OLLAMA_MODEL="qwen2.5:3b"
python -m uvicorn server:app --reload
```

Windows PowerShell:
```powershell
$env:OLLAMA_MODEL = "qwen2.5:3b"
python -m uvicorn server:app --reload
```

> ⚙️ Если Ollama недоступна, чат продолжит работать: сервер вернёт ошибку `Модель недоступна`, но базовые эндпоинты (триаж по правилам, SOAP, PDF, OCR-заглушка) продолжат отвечать.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434/api/chat` | Адрес Ollama-эндпоинта |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Имя модели в Ollama |
| `SMTP_HOST` | *(пусто)* | SMTP-сервер. Если пусто — включается демо-режим отправки |
| `SMTP_PORT` | `587` | Порт SMTP (STARTTLS) |
| `SMTP_USER` | *(пусто)* | Логин SMTP |
| `SMTP_PASS` | *(пусто)* | Пароль SMTP |
| `SMTP_FROM` | = `SMTP_USER` | Адрес отправителя |

Пример `.env`-подобного запуска:

```bash
export SMTP_HOST="smtp.yandex.ru"
export SMTP_PORT="587"
export SMTP_USER="helpinator@yandex.ru"
export SMTP_PASS="app-password"
export SMTP_FROM="helpinator@yandex.ru"
python -m uvicorn server:app --reload
```

Если SMTP не задан, эндпоинт `/api/send-protocol` вернёт `mode: "simulated"` — фронтенд покажет «PDF сформирован и отправлен (демо-режим SMTP)». Это удобно для демонстрации на хакатоне без боевого ящика.

## API-эндпоинты

Все эндпоинты принимают/возвращают JSON (кроме `/api/login` — там multipart/form-data).

### Авторизация

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/login` | Вход. Form-data: `name`, `email`, `consent=true`, `avatar` (файл, опц.) |
| `GET`  | `/api/me` | Данные текущего пользователя. `401`, если не залогинен |
| `POST` | `/api/logout` | Выход (удаляет cookie-сессию) |

### Анамнез и триаж

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/triage` | `{"text": "..."}` → `{level: red/yellow/green, emergency: bool}` |
| `POST` | `/api/complaints` | Добавить жалобу. Вернёт следующий уточняющий вопрос от Qwen |
| `POST` | `/api/reset` | Очистить список жалоб в сессии |
| `GET`  | `/api/soap` | Сформировать SOAP-протокол на основе жалоб |

### Рецепты и напоминания

| Метод | Путь | Описание |
|---|---|---|
| `GET`    | `/api/user-data` | Список рецептов и напоминаний |
| `POST`   | `/api/prescriptions` | Добавить рецепт |
| `DELETE` | `/api/prescriptions/{id}` | Удалить рецепт |
| `POST`   | `/api/reminders` | Добавить напоминание |
| `DELETE` | `/api/reminders/{id}` | Удалить напоминание |

### PDF и OCR

| Метод | Путь | Описание |
|---|---|---|
| `GET`  | `/api/protocol.pdf` | Скачать PDF-протокол |
| `POST` | `/api/send-protocol` | `{"email": "..."}` → отправить PDF врачу |
| `POST` | `/api/ocr` | Загрузка файла → распознанные препараты (заглушка) |

## Безопасность и 152-ФЗ

Проект разрабатывался с учётом требований **152-ФЗ «О персональных данных»**:

1. **Все вычисления — локально.** Языковая модель Qwen развёрнута через Ollama в том же контуре, где работает приложение. Медицинские данные не передаются в сторонние API (OpenAI, Anthropic, Google и т.п.).
2. **Явное согласие на обработку ПД.** На экране авторизации обязательна галочка согласия с 152-ФЗ — без неё вход невозможен.
3. **HttpOnly cookie.** Сессия хранится в HttpOnly-куке (`SameSite=Lax`), недоступной для JS.
4. **TTL сессии — 24 часа.** Просроченные сессии автоматически удаляются при каждом запросе.
5. **Ограничение на размер файла аватара** — 5 МБ, только изображения (белый список расширений).
6. **Отсутствие записи на диск персональных данных.** Анамнез, рецепты и напоминания хранятся только в оперативной памяти сервера и живут в рамках сессии.

### Ограничения прототипа

- Хранилище сессий — **в памяти** (`SESSIONS`). При перезапуске uvicorn все данные теряются. Для продакшена — Redis / PostgreSQL с шифрованием.
- SMTP-трафик в демо-режиме не отправляется по сети.
- Модель Qwen 3B **не является медицинским изделием**. Она не ставит диагнозы и не назначает лечение; все решения остаются за врачом.

## Клинико-экономический эффект

| Метрика | Эффект |
|---|---|
| **Снижение нагрузки на терапевта** | Предварительный анамнез собран в структурированном виде → меньше времени на расспросы, ~2–3 минуты экономии на приёме |
| **Снижение операционных издержек** | Меньше повторных обращений за счёт корректной маршрутизации и напоминаний |
| **Раннее выявление неотложных состояний** | LLM-триаж подсвечивает red-флаги и предотвращает самолечение |
| **Удержание пациентов** | Единая точка входа в цифровой канал ЕМИАС, персонализированное сопровождение |
| **Рост удовлетворённости** | Диалоговый формат вместо бланков и очередей |
| **Доля MedTech B2G** | Готовый прототип для интеграции в контур государственного здравоохранения |

## Лицензия и дисклеймер

Проект создан в рамках хакатона **SBERMED AI**. Не является медицинским изделием и не предназначен для постановки диагноза или назначения лечения. Любые выводы ИИ носят информационный характер и требуют подтверждения врачом.

При возникновении симптомов, угрожающих жизни, немедленно звоните:
- **112** — единый номер экстренных служб
- **103** — скорая медицинская помощь
